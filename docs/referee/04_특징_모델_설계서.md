- 결정 전에는 **임시 기본값**으로 작업함.
- F1·F2·F3은 10장 실험(E-01~E-03) 결과로 결정할 것을 권장함.

> [!warning] 결정 대기 — F1 Frame Feature 구성
> 임시 기본값: ② 수업 38-D + 신호 특화 특징
> - ① 장점: 수업 코드 그대로 사용, 비교 기준(Baseline)으로 적합
> - ① 단점: 관절각도 4개(팔꿈치·무릎)만으로는 손목 사이 거리, 손이 어깨에 닿았는지 등 혼동 짝의 차이를 직접 표현하지 못함
> - ② 장점: 검토자료 4번의 구분용 특징(손목 사이 거리, 손등~어깨 거리, 팔꿈치 각도, 궤적)을 그대로 반영
> - ② 단점: 특징 계산 코드 추가 필요
> - 진행 방법: ①로 Baseline을 먼저 만들고 ②와 Macro F1 비교 (E-01)

> [!warning] 결정 대기 — F2 윈도우 길이
> 임시 기본값: ② 1.5초
> - 짧은 동작(A02·A11·A12)은 약 1초, 반복·회전(A05~A09, A13)은 2~3회 반복에 약 1.5~2초 필요
> - 너무 짧으면 반복·회전의 주기가 안 담기고, 너무 길면 신호가 바뀌는 순간 반응이 늦어짐
> - 진행 방법: 1.0 / 1.5 / 2.0초로 각각 학습해 비교 (E-02)

> [!warning] 결정 대기 — F3 Sequence Feature 방식
> 임시 기본값: ② 통계 요약
> - ① 장점: 시간 순서 정보 보존 / 단점: 차원이 커지고(30 × 48 = 1,440), 동작 속도가 다르면 같은 신호도 값이 크게 달라짐
> - ② 장점: 속도·반복 횟수 차이에 덜 민감, 차원이 작음(약 300) / 단점: 순서 정보 일부 손실 → 처음·끝 변화량, 방향 전환 횟수로 보완

> [!warning] 결정 대기 — F5 실시간 확정 규칙
> 임시 기본값: 같은 예측이 **4번 연속**(stride 0.25초 기준 약 1초)이고 평균 확률 **0.6 이상**일 때 확정
> - 근거: 수업 7일차 예측 안정화, 검토자료 5번 '같은 결과가 일정 시간 이어질 때만 확정'
> - K·τ가 크면 오인식은 줄지만 반응이 늦어짐 → 실시간 시험에서 조정

## 3. 용어

| 용어 | 정의 |
| --- | --- |
| Frame Feature | 한 프레임의 자세를 표현한 숫자 벡터 |
| 윈도우 (Window) | 연속된 프레임 묶음. 길이 W초 |
| Stride | 다음 윈도우까지 이동 간격. S초 |
| 리샘플 | 윈도우를 시간 기준으로 T개 시점에 맞춰 다시 뽑는 것. FPS가 흔들려도 길이 고정 |
| Sequence Feature | 윈도우 하나를 Random Forest 입력 1개로 만든 벡터 |
| scale | `01` 문서 D2의 길이 단위 (몸통 길이 또는 어깨너비) |
| P_k | k번 Keypoint의 정규화 2D 좌표 (x, y) |

- 이미지 좌표 기준 y는 아래쪽이 +. 이 문서의 '높이'는 **−y** (위쪽이 큰 값)로 계산함.

## 5. Frame Feature

### 5.1 기본 38-D (수업 3일차)

| 구성 | 차원 | 내용 |
| --- | --- | --- |
| 정규화 좌표 | 34 | 0~16번 Keypoint의 (x, y). 원점 = 골반 중점, 단위 = scale |
| 관절각도 | 4 | 왼팔꿈치(5-7-9), 오른팔꿈치(6-8-10), 왼무릎(11-13-15), 오른무릎(12-14-16) |

- 관절각도 4개의 구성은 수업 3일차 코드와 대조해 확인 필요 (위 구성은 3일차 개요 기준 추정)
- 0~4번은 `01` 문서 M-05에 따라 모두 H로 같은 값 → 수업 코드 호환을 위해 그대로 둠

### 5.2 신호 특화 특징 (F1 = ② 일 때 추가)

- 근거: 모션캡처 검토자료 4번 구분용 특징 + 동작 정의서 '인식 포인트'
- 모든 거리는 scale로 나눈 값. 높이는 −y 기준

| ID | 특징 | 계산 | 구분 대상 |
| --- | --- | --- | --- |
| G-01 | 손목 사이 거리 | ‖P9 − P10‖ | 손을 모으는 신호(A02·A03·A04·A06·A15) ↔ 벌리는 신호(A07) |
| G-02 | 오른손목 높이 | −(y10 − yH) | C01·A03(머리 위) ↔ A02(가슴 아래) |
| G-03 | 왼손목 높이 | −(y9 − yH) | 양손 신호 구분 |
| G-04 | 오른손목–오른어깨 거리 | ‖P10 − P6‖ | A09(어깨에 닿음) ↔ A08 |
| G-05 | 오른팔꿈치–오른어깨 높이차 | −(y8 − y6) | A08(어깨 높이) ↔ A12(골반 높이), A11(어깨 위) |
| G-06 | 오른어깨 각도 | ∠(12-6-8) 골반–어깨–팔꿈치 | 팔을 든 정도 |
| G-07 | 왼어깨 각도 | ∠(11-5-7) | 팔을 든 정도 |
| G-08 | 손목 교차 | (x9 − x10)의 부호 | A15(아래팔 X자) |
| G-09 | 손목–같은 쪽 골반 거리 평균 | (‖P9 − P11‖ + ‖P10 − P12‖) / 2 | A01(양손 허리) |
| G-10 | 오른발목 앞으로 내밈 | ‖P16 − P15‖ | A10(발 내밀기) |
| G-11 | 오른손등 방향 각도 | 손목 10 → 손등 18 벡터의 각도 | A04(수평·수직), A05(손바닥 세움). F6 = ② 일 때만 |
| G-12 | 오른손등–오른어깨 거리 | ‖P18 − P6‖ | A09. F6 = ② 일 때만 |

- 차원: 38 + 10 = **48-D** (F6 = ② 이면 + 2 = 50-D)
- 오른손 통일(`03` 문서 W5) 기준으로 오른쪽 위주 특징 설계. 좌우 반전 데이터는 반전 후 같은 공식으로 계산하므로 별도 처리 불필요

### 5.3 계산 규칙

| ID | 규칙 |
| --- | --- |
| FR-01 | Frame Feature는 `01` 문서 P-5 정규화가 끝난 좌표로만 계산 |
| FR-02 | 학습(VICON 투영·웹캠)과 추론에 **같은 함수**를 사용. 코드 1벌 (`src/features.py`) |
| FR-03 | 결측 점은 `01` 문서 D5 규칙으로 채운 뒤 계산. 채울 수 없는 프레임은 윈도우에서 제외 |
| FR-04 | 각도 단위는 도(°), 범위 0~180 |

## 6. 윈도우와 학습 샘플

### 6.1 윈도우 파라미터

| 파라미터 | 기호 | 임시 기본값 | 비고 |
| --- | --- | --- | --- |
| 윈도우 길이 | W | 1.5초 | F2 |

| 리샘플 시점 수 | T | 30 | 시간 기준 선형 보간. 수업 6일차 고정 길이 Sequence |

### 6.2 학습 샘플 생성 규칙

| ID | 규칙 |
| --- | --- |
| WS-01 | `labels.csv`의 구간 위에서 윈도우를 S_train 간격으로 이동하며 생성 |
| WS-02 | 윈도우 안 프레임의 **70% 이상**이 같은 라벨이면 그 라벨을 윈도우 라벨로 사용 |

| WS-04 | 신호 구간이 W보다 짧으면 구간 중앙에 맞춘 윈도우 1개를 생성 (구간 밖 프레임 포함 허용) |
| WS-05 | 같은 클립에서 나온 윈도우는 학습·검증·테스트 중 한쪽에만 들어감 (사람 단위 분할, `02` 문서 8장 7단계) |
| WS-06 | VICON 투영의 각도·반전 파일은 원본 Take와 같은 사람(P001)으로 취급 |

## 7. Sequence Feature

- F3 = ② 통계 요약 기준. 윈도우 `[T, D]`에서 아래 값을 계산해 1개 벡터로 연결

| ID | 통계 | 계산 (Frame Feature 차원마다) | 담는 정보 |
| --- | --- | --- | --- |
| SQ-01 | 평균 | mean | 대표 자세 |
| SQ-02 | 표준편차 | std | 움직임 크기 |
| SQ-03 | 최솟값 | min | 동작 범위 |
| SQ-04 | 최댓값 | max | 동작 범위 |
| SQ-05 | 처음–끝 변화량 | f[T−1] − f[0] | 움직임 방향 (순서 정보 일부) |
| SQ-06 | 평균 속도 | mean(\|f[t+1] − f[t]\|) | 빠르기 |

추가 특징 (반복·회전 신호용):

| ID | 특징 | 계산 | 구분 대상 |
| --- | --- | --- | --- |
| SQ-07 | 오른손목 x 방향 전환 횟수 | x10 속도의 부호가 바뀐 횟수 | A05·A13(좌우·앞뒤 반복) |
| SQ-08 | 오른손목 y 방향 전환 횟수 | y10 속도의 부호가 바뀐 횟수 | A07·A09(위아래 반복) |
| SQ-09 | 두 손목 높이차 부호 전환 횟수 | (y9 − y10)의 부호가 바뀐 횟수 | A06(높이가 번갈아 바뀜) ↔ A07 |
| SQ-10 | 오른손목 이동 경로 길이 | Σ‖P10[t+1] − P10[t]‖ | 정지 신호 ↔ 움직이는 신호 |

- 차원: 48 × 6 + 4 = **292** (F1 = ① 이면 38 × 6 + 4 = 232)

## 8. 모델과 학습

### 8.1 모델

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 모델 | Random Forest (scikit-learn `RandomForestClassifier`) | 수업 6일차 Baseline |
| n_estimators | 300 | 시작값. 실험으로 조정 |
| max_depth | None | 시작값 |
| class_weight | `balanced` | N00이 많아 생기는 불균형 보정 (`02` 문서 5.5) |
| random_state | 42 고정 | 재현성 (수업 10일차) |
| 출력 | 17개 클래스 확률 (A01~A15, C01, N00) | X는 학습에서 제외 |

### 8.2 데이터 분할 (사람 단위)

| 용도 | 데이터 | 비고 |
| --- | --- | --- |
| 학습 | VICON P001 투영(전 각도·반전) + 웹캠 train 인원 | F4에 따라 웹캠 투입 시점 조정 |
| 검증 | 웹캠 train 인원 중 1명 (교차 검증 시 사람 단위로 돌아가며) | 하이퍼파라미터·F1~F3 결정용 |
| 테스트 | 웹캠 test 전용 인원 (`03` 문서 5장) | **최종 1회만** 사용 |

> [!warning] 결정 대기 — F4 학습 데이터 투입 순서
> 임시 기본값: ① 단계적 투입 (비교 문서 권장 절차)
> 1. VICON 투영 데이터만으로 학습
> 2. 웹캠 데이터로 검증 → VICON만으로 얼마나 통하는지 확인
> 3. 정확도가 낮거나 혼동되는 신호를 중심으로 웹캠 학습 데이터 추가 후 재학습
> 4. 학습에 쓰지 않은 사람의 웹캠으로 최종 평가
> - ② 처음부터 섞기: 절차는 단순하지만 VICON 데이터만의 효과를 확인할 수 없음

### 8.3 평가 지표 (요약)

- Accuracy, Macro F1, 혼동행렬 (수업 6일차)
- 오분류 윈도우는 원본 영상과 연결해 확인 (수업 6일차)
- 상세 절차와 목표 수치는 평가 계획서에서 정의

## 9. 실시간 추론 규칙

| ID | 규칙 |
| --- | --- |
| RT-01 | 프레임마다 19점 변환·정규화 → Frame Feature 계산 후 버퍼에 저장 |
| RT-02 | 버퍼에 W초 이상 쌓이면 S_rt마다 윈도우 구성 → 리샘플 → Sequence Feature → 예측 |
| RT-03 | 사람이 검출되지 않은 프레임이 0.5초 이상 이어지면 버퍼 초기화 |
| RT-04 | 확정 조건 (F5): 같은 클래스가 K번 연속 예측되고 그 확률 평균 ≥ τ |
| RT-05 | N00 확정 시 화면에 신호 표시 안 함 |
| RT-06 | 확정 전에는 '판정 중' 표시, 최고 확률이 τ 미만이면 '확인 필요' 표시 |
| RT-07 | 순서 규칙: C01 확정 후 3초 안에 확정된 신호를 하나의 판정으로 묶어 표시 (예: 시계 정지 → 블로킹) |
| RT-08 | A14는 C01 확정 후 3초 안에 바닥 가리키기가 확정될 때만 표시 (`02` 문서 L3) |
| RT-09 | 같은 신호가 확정된 뒤 N00이 확정되기 전까지는 같은 신호를 다시 표시하지 않음 (중복 방지) |

{
