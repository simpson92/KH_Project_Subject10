- 2026-11-17 본 촬영 전 결정 회의에서 W1·W2·W4 결정 (3장 W7~W9 함께 결정). W3은 미결정 — 본 촬영 후 다시 논의.
- 아래 회의 안건 상자는 결정 근거 기록으로 남겨 둠.

> [!warning] 회의 안건 — W1 촬영 각도 (정면만 vs 여러 각도)
> 임시 기본값: ① 정면만 촬영 + 최종 평가용으로 사선(±30°) 소량
> - ① 장점: 촬영량 1/5, 카메라 1대·고정 위치로 단순. 각도 다양성은 VICON 투영(0°/±30°/±60°)이 담당
> - ① 단점: 실제 데모 카메라가 정면이 아니면 웹캠 데이터로 각도 차이를 검증할 수 없음
> - ② 장점: 실제 환경과 같은 각도별 데이터 확보
> - ② 단점: 촬영량 5배 (카메라 5대 동시 또는 5회 반복)
> - 회의 전 확인: **데모 때 카메라를 어디에 둘지** 먼저 정하면 판단이 쉬움
> - 영향: `01_관절_매핑_명세.md` D3(투영 각도)는 W1과 별개로 유지 가능

> [!warning] 회의 안건 — W2 일상 동작 촬영 (박수·가리키기·휘슬)
> 임시 기본값: ① 포함 (동작당 촬영자 1인 2~3회, 짧게)
> - ① 장점: 실시간에서 박수·가리키기를 신호로 오인식하는 문제 예방 (검토자료 3번)
> - ① 단점: 촬영·라벨링 양 증가
> - ② 장점: 촬영 단순
> - ② 단점: 신호 없음(N00) 데이터가 Take 앞뒤 Neutral만 남아 오인식 위험
> - 특히 손가락 가리키기(↔A10·A14), 머리 긁기(↔A11), 팔짱(↔A15)은 신호와 모양이 비슷해 효과가 큼
> - 영향: `02_라벨링_가이드.md` 5.5 N00 수집 규칙

> [!warning] 회의 안건 — W3 신호 사이 차렷·걷기 구간
> 임시 기본값: ① 포함하되, 신호 단위 클립과 별도로 '연속 시나리오' 클립을 소량 촬영
> - ① 장점: 실제 경기처럼 신호가 띄엄띄엄 나오는 상황 재현 → 실시간 Sliding Window·예측 안정화(수업 7일차) 검증 가능. N00 데이터 확보
> - ① 단점: 클립이 길어지고 라벨링 구간 증가
> - ② 장점: 라벨링 단순 (클립 1개 = 신호 1개)
> - ② 단점: 실시간 연속 입력에서의 오인식을 테스트할 데이터 없음
> - 영향: `02_라벨링_가이드.md` 5.2 구간 구조 (연속 시나리오는 클립 1개에 신호 여러 개)

## 3. 결정 사항

| ID | 결정 내용 | 상태 | 비고 |
| --- | --- | --- | --- |
| W5 | 손 드는 신호는 **오른손으로 통일** | ✅ 결정됨 | 시계 정지(손 들기)와 한 손 신호 모두 오른손. 왼손잡이도 오른손으로 촬영 |
| W6 | 손 들기(시계 정지)는 **별도 클래스로 라벨링** | ✅ 결정됨 | `02_라벨링_가이드.md` L1 ① (C01) 확정 |

> [!success] 결정됨 — W5 오른손 통일
> - 시계 정지(손 들기), 한 손으로 하는 신호는 모두 오른손으로 수행
> - 왼손 데이터는 촬영하지 않고 좌우 반전으로 생성 (`01_관절_매핑_명세.md` M-09~M-11)
> - 촬영 중 왼손을 쓴 시도는 RESHOOT 처리 (10장)

| W7 | 영상 방향 **세로 1080×1920 · 30 FPS** (실시간 웹캠도 세로) | ✅ 결정됨 | 2026-11-17. 처음 결정(가로)을 촬영 위치 점검 후 변경 |
| W8 | 복장 **반팔 또는 소매 걷기** | ✅ 결정됨 | 2026-11-17. 손 검출 실험(`reports/team_projects/team01/hand_detect_report.md`): 긴 소매가 손 검출 실패의 주원인 |
| W9 | 테스트 전용 **S02**, **S01은 반드시 학습용** | ✅ 결정됨 | 2026-11-17. S01 = VICON 배우 KHM (`01` T-01) → 학습 쪽에 둬야 누수 없음 (`04` 8.2) |

> [!success] 결정됨 — W6 손 들기 별도 라벨링
> - 모든 신호 Take에 '손 들기 → 신호' 순서를 포함해 촬영
> - 손 들기 구간은 C01, 신호 구간은 A01~A15로 따로 라벨링
> - 손 모양: 파울 = 주먹, 바이올레이션 = 손바닥 (동작 정의서 기준). 단, 라벨은 둘 다 C01
- **일상 동작(D01~D03) Take에는 C01을 넣지 않음** — 실제 경기에서 휘슬·팔짱 앞에 손을 들지 않음. C01 뒤에 일상 동작이 오는 잘못된 순서를 학습하지 않게 함

> [!success] 결정됨 — W7 영상 방향 세로 (2026-11-17)
> - 사람 1명 전신이면 YOLO 입력(640)에서 세로가 가로보다 사람이 약 1.8배 크게 잡힘 (세로 360×640 중 키 약 600 px ↔ 가로 640×360 중 약 330 px)
> - 세로는 전신이 약 2 m 거리에서 들어와 촬영 공간 제약이 작음. Feature는 골반 중심·어깨 폭 정규화라 화면 방향과 무관
> - 학습 영상과 실시간 입력의 방향을 같게 유지: 7일차 IP Webcam은 "영상 보는 방식 → 세로 보기" (PC에서 frame 높이 > 너비 확인, 안 되면 `cv2.rotate`) → `05` 문서 반영 필요 (12장)

## 5. 촬영 규모

- 근거: 'YOLO Pose COCO 17과 MediaPipe Pose 33 비교' 문서의 단계별 수집 예시 (15개 동작 기준)

| 단계 | 인원 × 신호 × 반복 | 신호 클립 수 | 용도 |
| --- | --- | --- | --- |
| 기능 작동 확인 | 2명 × 15 × 3회 | 90 | 파이프라인 동작 확인 |
| 초기 모델 실험 | 3명 × 15 × 5회 | 225 | |
| 권장 기초 실험 | 5명 × 15 × 5회 | 375 | **W4 결정** |
| 성능 개선 실험 | 10명 × 15 × 5회 | 750 | 여유 시 |

- 촬영 인원 중 **1~2명은 테스트 전용**으로 지정, 학습에 사용 금지 (수업 5일차 Subject-wise Split) → **W9: S02**
- 테스트 전용 인원은 촬영 전에 미리 지정해 `person_id`로 관리
- 일상 동작(W2)·연속 시나리오(W3)는 위 신호 클립 수와 별도

## 6. 촬영 환경 사양

- 측정값은 모두 촬영 로그에 기록. `01_관절_매핑_명세.md` 7.3의 `camera` 값(VICON 투영용)으로 그대로 사용

| 항목 | 기준 | 비고 |
| --- | --- | --- |
| 카메라 | 스마트폰 기본 카메라 앱 **동영상 모드** (실시간 7일차는 IP Webcam 세로 보기) | 기종 기록. 사진 모드는 화면 범위가 달라 위치 확인에 쓰지 않음 |
| 해상도·FPS | **세로 1080×1920 · 30 FPS** (W7) | 촬영 중 변경 금지. 노출·초점 고정(AE/AF 잠금) |
| 카메라 높이 | 촬영자 가슴~어깨 높이 (약 1.2~1.5 m) | 실측값 기록 |
| 촬영 거리 | 머리 위로 쭉 편 손끝 위·발 아래에 각각 화면의 약 10% 여유, 양팔을 옆으로 뻗어도 화면 안 (세로 기준 약 2 m 안팎) | 실측값 기록. 바닥에 서는 위치·폰 위치 테이프 표시. 어깨 폭 60 px 이상 (손 검출 실험 기준) |
| 카메라 각도 | **정면만** (W1) | 정면 = 촬영자 몸 정면과 카메라가 마주 봄 |
| 배경 | 무늬 없는 벽, 화면 안에 다른 사람·사람 사진(포스터·모니터 화면) 없음 | 다른 사람 등장 시 RESHOOT. 화면 속 사진도 YOLO가 사람으로 잡음 |
| 조명 | 역광 금지, 실내 조명 고정 | |
| 복장 | 몸 윤곽이 보이는 옷, 배경과 대비되는 색, **반팔 또는 소매 걷기** (W8) | 헐렁한 옷·긴 소매 금지 |
| 파일 옮기기 | **USB 케이블 · 구글 드라이브 등으로 원본 그대로** | 카카오톡은 영상을 다시 압축하고 촬영 시각을 지우며 순서가 섞임 (11-17 1차 촬영에서 확인) |
| 촬영자 위치 | 화면 가로 중앙, 상하 여백 확보 | partial_body 방지 (수업 2일차) |

## 7. 촬영 절차

### 7.1 전체 흐름

| 단계 | 작업 | 산출물 |
| --- | --- | --- |
| S-1 | 촬영 환경 설치·측정 (6장) | 촬영 로그 헤더 값 |
| S-2 | 시험 촬영: 1명이 신호 3~4개 촬영 | 시험 클립 |
| S-3 | 시험 클립 품질 확인: 수업 2일차 방식으로 Keypoint Confidence 확인 (10장 기준) | 통과 시 본 촬영 진행 |
| S-4 | 본 촬영: 촬영자별 A01~A15 × 반복 횟수 | 신호 클립 |
| S-5 | (W2) 일상 동작 촬영 | 일상 동작 클립 |
| S-6 | (W3) 연속 시나리오 촬영 | 시나리오 클립 |
| S-7 | 촬영 직후 재생 확인 → RESHOOT 즉시 재촬영 | 촬영 로그 result |

### 7.2 신호 클립 1개 구성

| 순서 | 구간 | 시간 | 라벨 (02 문서) |
| --- | --- | --- | --- |
| 1 | 차렷 (Neutral) | 약 2초 | N00 |
| 2 | 오른손 들기 → 유지 | 약 1~2초 | C01 |
| 3 | 신호 수행 | 동작 정의서 기준 | A01~A15 |
| 4 | 차렷 복귀 | 약 2초 | N00 |

- 1클립 = 신호 1회. 반복은 클립을 나눠 촬영 (Take `T01`, `T02` …)
- 시작·끝 차렷 2초는 라벨 경계를 잡기 쉽게 하고 N00 데이터로도 사용

### 7.3 동작 변형 배분 (반복 5회 기준)

| Take | 변형 | 근거 |
| --- | --- | --- |
| T01 | 보통 속도·보통 크기 | 기준 |
| T02 | 보통 속도·보통 크기 | 기준 |
| T03 | 빠르게 | 검토자료 2번 (실제 심판은 더 빠르고 짧음) |
| T04 | 느리게 | 검토자료 2번 |
| T05 | 크게 또는 작게 (촬영자별 번갈아) | 검토자료 2번 |

- 반복 3회 단계면 T01 보통, T02 빠르게, T03 작게
- 변형 내용은 촬영 로그 `variation` 컬럼에 기록

### 7.4 헷갈리는 짝은 연속 촬영

- 검토자료 4번 대응. 아래 짝은 촬영 순서를 붙여서 차이를 크게 연기

### 7.5 일상 동작 (W2 포함 시)

W2 결정(2026-11-17)으로 코드를 아래 3개로 확정. 회의 전 후보 번호(D01 박수 … D05 팔짱)는 쓰지 않음.

| 코드 | 동작 | 반복 | 헷갈리는 신호 | 정의 |

### 7.6 연속 시나리오 (W3 포함 시)

- 구성 예: 차렷 3초 → 걷기 5초 → 손 들기 → 신호 → 차렷 3초 → 걷기 5초 → 손 들기 → 신호 …

| 종류 | 형식 | 예시 |
| --- | --- | --- |
| 신호 클립 | `T01_S##_A##_T##.mp4` | `T01_S03_A05_T02.mp4` |
| 일상 동작 클립 | `T01_S##_D##_T##.mp4` | `T01_S03_D01_T01.mp4` |

| 촬영 로그 | `webcam_log.csv` | `reports/team_projects/team01/main/webcam_log.csv` (Git 관리, `scripts/day05_team_make_webcam_log.py`가 manifest에서 채움 — 카메라 높이 · 거리 · 진행자는 사람이 기입) |

- 글자 뜻은 `01` 문서 7.1 (수업 4일차 형식). `S##` = 촬영자 ID (01부터). **VICON 배우(KHM, `S01` 확정)와 같은 사람이면 같은 S번호를 쓰고 `01` 문서 후속 작업 11로 VICON 쪽 번호를 맞춤**
- 저장 위치: 원본(폰에서 옮긴 그대로)은 `data/raw/webcam/`, clip_id 이름 복사본은 **`data/team_projects/team01/main/rgb/videos/`**
- **스모크 100개와 폴더를 나눔** — 스모크도 `T01_S##_A03·A05_T01~T10` 이름이라 같은 폴더면 덮어쓰기, STEP 4가 "이미 있음"으로 건너뜀. manifest는 `configs/team01_main_manifest.csv`
- RESHOOT 클립은 삭제하지 않고 로그에 `RESHOOT`으로 남긴 뒤, 재촬영본은 Take 번호를 이어서 부여 (예: T02 실패 → T06)
